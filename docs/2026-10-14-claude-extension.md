The new cohort is `fixed81_strict_claude_extension_20261014_r1`; its plan is [2026-10-14-claude-extension-plan.json](2026-10-14-claude-extension-plan.json). The original Gemini watchdog holds the privately supplied keyring passphrase only in its process environment. The coordinator first reserves the shared computation lock, verifies the watcher identity and idle state, then parks that same process with SIGSTOP after verifying there is no active computation. A raced startup is rolled back before extension dispatch. The new extension has a distinct singleton watcher lock, acquired before publishing its PID; it retains the original global computation and authentication locks. No runtime-state directory or held lock is replaced.

The coordinator releases Gemini with SIGCONT only after all 324 extension pairs are complete, frozen identities and cleanup are verified, and user pause guards on both roots remain clear. A user pause drains admitted extension pairs and cancels the automatic handoff. A coordinator failure leaves Gemini parked; recovery uses the saved ownership token and process identities to reattach rather than creating a duplicate controller. A zero exit from a partially drained run does not authorize Gemini continuation.

The host-side Claude identity check now accepts only the exact requested ID or its eight-digit dated snapshot. This prevents `claude-opus-5-5` or `claude-sonnet-5-5` from being accepted through a loose prefix match when the request is Opus 5 or Sonnet 5. The pinned Docker image, worker sources, prompts and original frozen controller are unchanged.
