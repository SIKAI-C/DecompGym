# 2026-10-12 Journey — 两项 prompt 决定与新一轮实验计划

本文件按用户要求使用 October 12 的日期命名；实际准备、代码修改与检查发生在 2026-10-11 EDT。本轮授权范围是修改 harness、检查 CLI、准备新实验计划、分组提交代码。正式 benchmark 与 hourly review 保持暂停；本轮没有初始化或启动新的生产 campaign。

## 用户决定与实验边界

决定一：generation 使用 `Only edit the existing solver.py in the current working directory.`；reflection 使用 `Only edit the existing debug.md in the current working directory.`。每次调用只指定一个目标文件，按实际文件名生成指令。该决定已经实现，取代之前较长的绝对路径提示。

决定二：不向 agent 提供 evaluator 的 reference objective、数值 objective gap 或由 reference 推导出的数值提示。当前候选解自己的 objective、solver 自行计算的 bound、stdout/stderr、约束检查问题和算法检查反馈仍可提供。内部评分继续计算和保存精确 reference/gap，以判断 pass、early stop 和生成报告。

对于执行成功、约束检查确认可行、候选目标与 reference 均有效、内部 gap 超出原有接受阈值的结果，harness 固定生成以下一句话；这不是 master agent 针对该实例写的分析：

```text
The current solution is feasible, but its objective value does not meet the required target. Please try again.
```

执行失败、超时、不可行、缺失目标值或缺失 reference 时不生成这句话。算法结构检查失败仍保留原有算法反馈；若同时确认约束可行且目标值检查失败，两类反馈可以同时存在。只因算法结构失败、而目标值已达标时，不生成目标值失败提示。

master agent 负责准备 harness、监控基础设施和记录证据。正式实验中，候选代码由被测模型生成，程序负责执行和可行性/目标值检查，独立 Astra-high judge 负责算法结构检查，被测模型自己生成 reflection；master agent 不逐例补充解题分析、不修改候选 solver、不编造通过结果。

旧实验、旧 prompt、reflection、调用回执、失败轨迹、评分与冻结 controller 全部保留。旧 cohort 不作为新协议的结果继续累计。新实验从空的 runs 开始，避免把旧 numeric-gap reflection 带入后续 context。用户明确保留 GPT-6 Astra 的历史 100% first-attempt 结果，不重跑 Astra。

## Prompt 前后对照与历史保存

Codex 原始文件指令如下；AGY 原始 prompt 还在最前面加入了下一段所示的绝对路径说明：

```text
Edit only solver.py. All task context is supplied below.
Edit only debug.md. All task context is supplied below.
```

```text
For this editing call, the workspace is `<temporary-workspace>`; edit only `<temporary-workspace>/<target>`.
```

新 generation 和 reflection 的第一句分别如下；原来紧接其后的 `All task context is supplied below.` 仍保留：

```text
Only edit the existing solver.py in the current working directory.
Only edit the existing debug.md in the current working directory.
```

旧 reflection 每轮包含以下模板行，`<gap>` 曾经被真实数值替换：

```text
The current objective gap to the optimal solution is: <gap>
```

该行已经移除。新 `PromptBuilder.build_reflection_prompt` 仅接受布尔参数 `objective_quality_failed`，拒绝数值或字符串参数；只有条件成立时才加入上面的固定英文提示。诊断类别中的 `objective-gap failures` 改为 `objective-quality failures`，不会把 reference 或数值 gap 拼入 prompt。

每次实际 CLI 调用保存 `<step>_prompt.md`（真正发送的全文）、`<step>_prompt_before_workspace.md`（同一次输入的旧 workspace 句式对照）、`<step>_workspace.json`（版本、实际工作区、目标路径及文本哈希）、invocation/events/metrics 回执。对照文件明确标记为 comparison only，不会发送给模型。它只对照 workspace 句式，不伪装成曾经发送过的旧数字反馈。Claude Code 是新加入的 backend，其旧句式对照也只是对照文本，不代表历史 Claude Code 调用。

过去真实的逐轮 prompt 继续保存在原始调用目录；已整理的多轮真实案例见 [October 11 五轮 Codex prompt walkthrough](2026-10-11-codex-five-round-prompt-walkthrough.md) 和 [October 11 journey](2026-10-11.md)。这些文件保留原始数值反馈作为研究历史，不作为新实验的 agent context。

上下文仍由 harness 读取允许的文件后拼入 prompt。generation 收到问题说明与 data.json；reflection 模式下后续 generation 额外收到之前各轮 solver.py/debug.md。reflection 收到当前轮的 data.json、solver.py、exec.log、alg_verifier.md、output.json；judge 只收到用于算法检查的 solver 内容。不会主动把 gold_monolithic.json、meta.json、score_receipt.json 或 instance_summary.json 放入 agent context。

每次 CLI 在新的临时目录中运行，目标文件预先存在；复制回来的只有指定目标。生成 solver 随后在独立的 attempt 运行目录执行。native solver 的文件读取能力仍受原有执行方式约束，本次改动没有把它变成一个新的 OS 级只读数据沙箱。

## Harness 实现

- `src/agent/prompt_policy.py` 集中定义 workspace/feedback 版本、目标文件指令、调用前后文本存档和错误路径产物存档。Workspace policy 为 `existing-target-cwd-v2`，feedback policy 为 `qualitative-objective-feedback-v1`。
- `src/agent/prompt_builder.py` 移除数字 gap 接口；`src/agent/experiment_runner.py` 与 `src/agent/paired_runner.py` 共用同一个定性反馈判定，不更改内部评分或接受阈值。
- `src/agent/codex_client.py` 和 `src/agent/agy_client.py` 使用简短现有文件指令；`src/agent/claude_client.py` 为新的 Claude Code backend。三者都保留实际 prompt、前后对照和工作区证据。
- `src/agent/policy_completion.py` 保留旧 `explicit-workspace-target-v1` phase 的验证逻辑，新增 fresh campaign 对 v2 错误路径证据的独立验证。模型完成调用后确实把非空 reflection 写到了错误目录时，保存证据并计为终止失败，不搬运错误文件、不自动补出下一轮，也不把未执行的预算槽计为生成尝试。认证、额度和网络失败仍归基础设施处理。
- 新 paired case 身份和 request fingerprint 含 prompt policy 版本，新的默认协议为 `native-qualitative-v2`，避免把旧 receipt 或旧 context 当成新协议继续使用。
- `src/campaign_plan.py` 验证显式计划；`src/native_campaign.py init --plan ...` 校验固定数据的 inventory hash，冻结新 controller 和模型队列，并创建暂停标记。初始化本身不启动模型。已有输出目录会被拒绝，输入不匹配会在创建新 campaign 前失败。
- 新 runtime 按 manifest 的 backend 路由 Codex、AGY、Claude Code；沿用两 worker、Codex 双槽且认证故障退回串行的 gate、AGY 串行调用；Claude Code 调用也串行。新 dashboard 按显式队列展示 Claude Code 的正确 backend 和模型名称。
